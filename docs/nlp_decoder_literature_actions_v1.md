# NLP decoder literature: findings and bounded actions

Date: 2026-11-04  
Scope: the current low-data structured decoder, strict AST recovery, and CPU-bound rollout path. This is an engineering synthesis, not a claim that a paper's result transfers to this repository.

## Project evidence being addressed

The frozen CPU head audit covers 403 training rows and 64 validation fragments. `node_kind` has 323 training classes, minimum support 1 and effective class count 20.56; validation accuracy is 0.593 and macro-F1 is 0.330. `edge_field` has 42 classes but effective class count 2.22; validation accuracy is 0.848 and macro-F1 is 0.367. The 158 observed `node_budget` values have support 1–13; validation accuracy is 0.141 and macro-F1 is 0.068. The parent head already uses legal candidates, with a validation mean candidate set of 17.72 and maximum 64. These are teacher-forced diagnostics, not free-running quality evidence.

The custom structured decoder has repeatedly failed to finish a matched GPU registration because another project line enters cuda:0. In v19, 10 of 12 checkpoints were saved before the ownership watchdog stopped only NLP; two hierarchical seeds were not started. The exact strict AST gate remains unchanged. Replay and prior runs have not shown a dependable end-to-end pass signal.

## 2026-11-05 matched head-screen result

The registered low-data head screen completed on 403 training rows and 64 validation fragments. Both the legacy control and the rank-32 grammar-masked node-kind plus residual-budget candidate produced 0 parser-valid outputs and 0 exact action-sequence matches. The candidate's node-kind teacher-forced accuracy rose from 0.597 to 0.612, while budget accuracy fell from 0.109 to 0.078; neither change transferred to free-running output. No executable cases were available because the frozen validation rows contain no bounded input/expected-output contract.

This result narrows the immediate failure: reducing class-specific head parameters and legal-candidate sets did not resolve free-running failure. The cited grammar-constrained decoding work supports legality masks, but this code already uses them; PICARD/XGrammar-style parser state alone is not evidence for task-level recovery. Following the registered negative-result rule, retain the legacy heads and stop this head-search branch. Any later NLP work must be separately admitted by the task graph and diagnose the recorded first-failure classes (syntactically malformed source or no legal action candidate) without relaxing the historical strict AST gate.

## Findings

| Source | Relevant result | Fit to this project | Action |
|---|---|---|---|
| Geng et al., EMNLP 2023, [Grammar-Constrained Decoding for Structured NLP Tasks without Finetuning](https://aclanthology.org/2023.emnlp-main.674/) | Input-dependent grammars improved structured extraction, entity disambiguation, and constituency parsing, with particular motivation for scarce data. | Supports using known grammar to narrow choices or a pretrained model's output. It does not show that grammar fixes missing task semantics, nor that this project's custom model will reach executable success. | Keep legal-candidate masking; score parser validity separately from execution and exact reconstruction. Do not add more grammar mechanisms before the current matched replay is analyzed. |
| Schmidt & Cimiano, *Frontiers in Artificial Intelligence* 2025, [Grammar-constrained decoding for structured information extraction](https://doi.org/10.3389/frai.2024.1406857) | On two clinical information-extraction datasets with at most 500 training examples, grammar-constrained decoding substantially improved F1. Their pointer-generator addition reduced F1 versus grammar-only models. | Closest small-data evidence, but its task is slot filling with a pretrained encoder-decoder, not source-code AST synthesis. It warns against assuming a copy head helps just because labels are sparse. | Keep the already provenance-checked lexical copy/generate path fixed. Consider pointer redesign only if a row-level audit identifies unseen identifiers as the dominant error and a matched ablation can test it. |
| Scholak et al., EMNLP 2021, [PICARD](https://aclanthology.org/2021.emnlp-main.779/) | Incremental parsing rejects inadmissible next tokens and improved fine-tuned T5 results on Spider and CoSQL. | Confirms that parser state can constrain an autoregressive decoder. The project already has grammar masks and completion checks; repeating this idea alone is unlikely to address the observed low semantic/task success. | Preserve the existing contract. Profile the cost and soundness of the current candidate mask before considering another parser integration. |
| Dong et al., MLSys 2025, [XGrammar](https://proceedings.mlsys.org/paper_files/paper/2025/file/5c20ca4b0b20b0bd2f1d839dc605e70f-Paper-Conference.pdf) | Prechecks context-independent token legality, caches adaptive masks, and uses persistent parser stacks; reports large mask-generation speedups in its LLM-serving workloads. | Directly relevant to repeated grammar-state work, but their decoder masks subword tokens for a large LM. This project predicts structured action families and its measured bottleneck includes Python-side completion accounting, so the paper's speedup is not a transfer estimate. | Reuse the design pattern, not the library or claimed multiplier: memoize immutable grammar-state transitions, cache legal candidate sets, and measure CPU time per action plus mask equivalence on existing fixtures before any GPU run. The relation-index and iterative completion-cache fixes already implement part of this direction. |
| Rabinovich et al., ACL 2017, [Abstract Syntax Networks](https://arxiv.org/abs/1704.07535) | Builds an AST with decoder modules whose structure mirrors the output tree. | This motivates tree-shaped prediction but does not establish sample efficiency for this dataset. The project's hierarchical arm has been costly and under-evidenced, so another architectural rewrite is not justified. | Finish the already registered replay first. Do not expand the hierarchical mechanism based on architectural analogy. |
| Nagy et al., [ChopChop](https://arxiv.org/abs/2509.00360), POPL 2026 | Checks whether a prefix has any completion satisfying an AST-level semantic property; experiments include type safety and equivalence. | Potentially relevant to the gap between syntactic legality and semantic correctness. It requires explicit, trusted task properties; this project cannot derive those properties from a reference AST at inference. | Treat semantic pruning as a later research branch only after defining target-free properties and proving the pruning sound. It is too costly and speculative for the current low-risk pass. |

## Recommended sequence

1. Finish CPU replay for the ten available v19 checkpoints and preserve the two untrained hierarchical arms as unavailable. Do not infer a four-arm winner from the partial registration.
2. Run the already frozen CodeT5-small pilot only after WP-068-B closes and cuda:0 is exclusively free. Treat its 24 validation cases as diagnostic; require source-disjoint confirmation for any positive claim.
3. If the pilot is positive, implement at most the two variants already named in WP-078-B: (a) shared grammar-conditioned legal-candidate scoring for sparse node/edge labels, and (b) a deterministic grammar-feasible minimum plus a small ordinal residual for preferred node budget. Keep the backbone and 23M budget cap fixed.
4. In CPU preflight, verify candidate masks are identical at training and inference, record candidate-set size, row-level class coverage, parameter count, and calibration. Compare against the frozen head using identical data, seed, optimization, and decoding. The screen must include full free-running parser and executable outcomes.
5. If the pilot is not positive, close the head branch with the existing simpler control. Do not implement these variants merely because teacher-forced head metrics are weak.

## Decision

The literature supports two bounded ideas: exploit known constraints to remove impossible choices, and reduce repeated grammar-state work through caching. It does not support a new custom hierarchy, an unverified pointer head, or a claim that syntactic validity will solve semantic task failure. The positive CodeT5 pilot opened the registered head screen, but its negative free-running result now closes that branch. Runtime caching can still be considered as an independently registered CPU performance task; it must not be presented as a fix for the observed zero parser-valid rate without new evidence.
