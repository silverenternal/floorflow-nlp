# 图路由梯度链诊断

## 设置

同一个固定合成样本（`single_link_retrieval`, data seed 91001，4 个样本中只取 index 0），在 CPU 和 MPS 上比较单步任务损失反传。数据、oracle 边和模块初始化 seed 固定；没有训练多个 step、选择超参或读取封存测试。机器与源码摘要保存在同目录 JSON。

## 观察

- 单独 `ModelNeuron` 前向没有入边：12 个参数张量中 10 个连接到梯度，message projection 和 edge type embedding 自然未触达；9 个有非零梯度。
- 固定 oracle 边：12/12 个参数连接到有限梯度（10 个非零）。所以正确消息路径可被当前神经元模型反传训练，但一次随机初始化的预测仍未拟合标签。
- 软候选路由：共享神经元 10/10、策略 8/8、readout 2/2 有梯度；策略梯度范数仅约 `0.0325`，远低于 neuron/readout 量级。四个候选的 argmax 全部是 connect-type-1。
- 硬前向 straight-through：策略重新收到非零梯度（范数约 `0.0555`），动作分布仍退化为四条 connect-type-1。
- 离散硬推理：策略 0/8 参数有任务梯度，这是硬 topology mutation 经 `detach/cpu` 的预期结果；神经元/readout 仍有梯度。阈值 0.4 下本例实际没有产生任何 mutation，说明硬决策置信度未达门槛。
- CPU 和 MPS 的损失、动作、梯度覆盖一致到浮点误差范围。

## 诊断结论

这次最小样本定位到两处可直接验证的训练问题：软候选策略梯度幅度很弱且初始动作偏向单一连接类型；硬离散动作本身不可微，必须依靠 straight-through 或结构监督等训练路径学习策略。当前证据不支持“ModelNeuron 完全没有梯度”这一解释：固定 oracle route 有完整神经元梯度。由于仅一个样本和一次反传，不能据此声称问题已修复，也无法区分所有泛化/结构可辨识问题。
