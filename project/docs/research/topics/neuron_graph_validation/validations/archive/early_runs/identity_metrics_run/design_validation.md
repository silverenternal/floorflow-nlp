# NE-018 匹配拓扑、参数对照与 MPS 成本验证

状态：六种子、80 步筛查完成。结果仍属小规模合成任务，不构成自然语言能力或统计显著性结论。

## 复现

- 指标契约：[metrics_contract.md](../../metrics_contract.md)
- 配置：[graph_validation_as_run.json](graph_validation_as_run.json)
- 运行器：[run_neuron_graph_validation.py](../../../../../../scripts/experiments/training/neurons/graph/run_neuron_graph_validation.py)
- 六种子逐项结果：[design_validation.json](design_validation.json)
- 命令：`uv run --extra dev python project/scripts/experiments/training/neurons/graph/run_neuron_graph_validation.py --output project/docs/research/topics/neuron_graph_validation/validations/identity_metrics_run/design_validation.json`
- 种子：11、23、37、41、53、67；每个条件 80 步，训练在 CPU，Apple MPS 只测候选生成和推理。
- 每条 32-token 序列由两个独立的 16-token 模加递归 segment 构成；segment 边界重置递归，并屏蔽跨段 next-token 监督。
- 每个图预算都与基础 Transformer 和参数匹配 Transformer 配对。基础/图模型分别 10,352/14,960 参数；参数匹配控制将 FFN intermediate size 从 64 增至 112，参数精确匹配 14,960，但计算量与归纳偏置不匹配。

| --- | ---: | ---: | ---: | ---: |
| 基础无图 | 10,352 | 3.486 ± 0.215 | 28.80% | 0.183 |
| 参数匹配无图 | 14,960 | 3.404 ± 0.226 | 31.15% | 0.189 |

| 图预算 | 对基础无图 | 对参数匹配无图 |
| ---: | ---: | ---: |
| 16 | -0.003 ± 0.087 | +0.079 ± 0.130 |

## 拓扑扰动与隔离

“matched_rewire”逐目标保留入度、边类型计数和 strength 多重集，只在相同 segment 的严格因果前缀内重采样来源。删除对照从已学拓扑随机移除 25%/50% 边；零消息对照保持同一模型和拓扑，只把图残差门置零。

| 候选预算 | 原图 CE | 匹配重连 CE | 删除 25% CE | 删除 50% CE | 关闭消息 CE |
| ---: | ---: | ---: | ---: | ---: | ---: |
| 16 | 3.483 | 3.497 | 3.496 | 3.512 | 3.571 |
| 64 | 3.471 | 3.483 | 3.484 | 3.491 | 3.559 |
| 256 | 3.524 | 3.532 | 3.520 | 3.517 | 3.555 |

所有候选预算的策略动作仍全为 keep，最终拓扑保持每个 16-token segment 内的初始化因果链。因此匹配重连的差值只说明当前链与重连样本的敏感性，不能当作“学到的拓扑优于随机图”的证据。段内因果性由扰动器强制并测试；段间连边在构造扰动时拒绝。

## MPS 与内存口径

batch=8 的 MPS 前向耗时中位数 / P95：

| 序列长 | 无图 | 图 |
| ---: | ---: | ---: |
| 32 | 0.85 / 1.13 ms | 10.58 / 10.99 ms |
| 64 | 0.83 / 0.87 ms | 10.69 / 11.26 ms |
| 128 | 0.95 / 0.96 ms | 10.77 / 11.29 ms |

序列长 512 的 MPS 候选生成预算 32/128/256 中位耗时约 0.929/0.952/0.935 ms，候选边索引分别 512/2,048/4,096 字节。此规模下 MPS 候选搜索慢于 v2 同机 CPU 筛查约 0.03 ms；小图的 MPS kernel/dispatch 成本占主导。

内存字段有意分开：

- 进程整次实验 RSS 高水位约 381 MiB，覆盖整个 runner，不归因于单个模型。
- 每个训练阶段使用 psutil 以 2 ms 间隔采样 RSS；budget 256 的采样峰值增量约 24.7 MiB。采样可能漏掉更短峰值，阶段起点也包含已实例化模型与运行环境。
- MPS 在 warmup 后对额外稳态前向同步采样 allocated/driver-allocated 计数。图模型 `current_allocated_memory` 采样峰值增量约 101/183/344 KiB（序列长 32/64/128）；序列长 128 的采样峰值与前向完成后持有输出时的 live delta 接近。driver 采样峰值增量均约 16 KiB（无图对照为 0）。2 ms 采样仍可能漏掉更短的峰值；PyTorch 没有在本 runner 使用的公开 MPS peak reset/read 接口，因此不把采样估计称为精确峰值。
- 参数字节数、CPU profiler 算子分配总和与 RSS 各自独立，不互相替代。

RSS 采集使用开发依赖 [psutil](https://psutil.io/api/) 的 `Process.memory_info().rss`；lock 版本为 7.2.2。完整配置、版本、哈希及每种子原始数值见 JSON。口径勘误：原配置快照已随结果归档为 [graph_validation_as_run.json](graph_validation_as_run.json)，其中曾把采样计数写成“快照”。当前 v3 配置已修正文案；结果 JSON 的 config_sha256 仍与归档 as-run 配置一致，所有测量值均未修改。

## 决策

这轮补齐了参数匹配、拓扑属性匹配扰动、距离桶梯度、三层表示诊断及 MPS/主机内存采集，但没有证明图模型带来稳定任务收益。特别是策略仍只保留初始化边，MPS 推理成本显著高于无图小模型。继续保持图层实验性、默认关闭；如推进结构学习，应先解决动作策略全 keep，再转向更具代表性的任务做确认性评估。
