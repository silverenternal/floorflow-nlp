- 记录 Python/Torch/平台、配置与关键实现文件的 SHA-256、每个种子的训练/验证数据摘要。原始 JSON 保留全部逐种子数值。

## 结果

| 条件 | 参数量 | 验证交叉熵（均值） | next-token 准确率（均值） | 80 步训练时间（均值） |
| --- | ---: | ---: | ---: | ---: |
| 无图基线 | 10,352 | 2.727 | 40.63% | 0.175 秒 |
| 图，预算 16 | 14,960 | 2.812 | 39.89% | 0.455 秒 |
| 图，预算 64 | 14,960 | 2.824 | 39.11% | 0.584 秒 |
| 图，预算 256 | 14,960 | 2.838 | 38.91% | 1.084 秒 |

这两个种子下，候选预算增大没有带来任务收益；图模型验证交叉熵较高、准确率较低，训练时间约为基线的 2.6–6.2 倍。图模型额外增加约 44.5% 参数，因此本次比较不是参数匹配实验，不应将差异归因于连线策略单一机制。

CPU 候选生成在序列长 512 时，中位耗时约为 0.032/0.033/0.038 ms（预算 32/128/256）；候选边索引占 512/2,048/4,096 字节。PyTorch CPU profiler 统计的正向算子分配量合计约为 32.5/54.9/84.7 KB。该值是算子分配量之和，不是峰值驻留内存。端到端 batch=8 前向耗时如下：

| 序列长 | 无图 | 有图（预算 64） |
| ---: | ---: | ---: |
| 32 | 0.270 ms | 0.807 ms |
| 64 | 0.493 ms | 1.145 ms |
| 128 | 1.216 ms | 1.985 ms |

候选构造在所测长度上保持低延迟，图层本身仍增加端到端耗时。候选生成正向算子分配量随预算增长；本轮未测峰值进程内存或完整模型峰值内存。

## 契约与决策

`NeuronGraphTopology` 现在可保存逐节点 `node_ids`。模型复用拓扑时必须同时提供完全匹配的 ID；缺失、重复、节点顺序变化或不同样本 ID 都会拒绝。padding 的节点 ID 为 `-1`。`PackedTokenDataset` 接受调用者分配的 `node_identity_namespace`，生成跨 epoch 可复现的 token ID；同一共享拓扑范围内 namespace 必须唯一。追加节点时必须提供新 ID。

硬拓扑修改只在 eval 模式接受，且必须配置有限全图边预算；训练模式维持可微软候选权重。这样硬更新发生在优化步之间，不在同一前向中混合离散拓扑和软期望边权。

当前探索性结果没有支持启用神经元图作为默认模型。保留模块供后续假设检验，默认继续关闭。进一步比较需增加种子、参数/计算对齐，并使用预先冻结的真实任务；还需测量峰值内存和 MPS 吞吐。节点仍是 token 位置，稳定 ID 解决的是拓扑复用错配，不是跨任务神经元注册或动态神经元增殖。
